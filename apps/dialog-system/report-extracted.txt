## 1. Literature Summary: GUS (Grandfather of Frame-Based Dialog Systems)

*Reference: Bobrow et al., "GUS, A Frame-Driven Dialog System" (1977)*

GUS established core principles for conversational assistants:
- **Frame-Based Knowledge Representation**: Representing dialog context as structured frames with slots (e.g., departure city, travel date, passenger count).
- **Mixed Initiative**: Allowing the system to prompt for missing slot values while allowing the user to provide unsolicited additional slot information.
- **Vague & Anaphora Resolution**: Parsing relative temporal expressions (e.g., "next Friday") into concrete dates.

## 2. System Architecture & Methodology

### 2.1 Multi-Domain Coverage
The assistant handles three distinct conversational domains:
1. 🌤️ **Weather Reports**: Querying location, date, temperature, humidity, precipitation, and wind speeds.
2. 🍽️ **Restaurant Search**: Querying city, cuisine types, ratings, and restaurant names.
3. ✈️ **Flight Travel Bookings**: Querying flight dates, airlines, flight numbers, departure cities, and destination cities.

### 2.2 Core Modules
- **TaskManager**: Handles SQL/Pandas dataframe queries against structured datasets (`weather_data.csv`, `North America Restaurants.csv`, `goibibo_flights_data.csv`).
- **ChatBoxUtility**: 
  - Tokenization & intent extraction.
  - Synonym expansion using NLTK WordNet (`nltk.corpus.wordnet`).
  - Fuzzy date parsing (`dateutil.parser`).
  - Regex entity extraction for geographic locations and flight parameters.
- **Multi-Turn Dialogue Engine**: Manages session state, detects missing required slots, prompts the user interactively, and formats natural language responses.
