## 1. Paper Summary: AlphaGo

This paper discusses DeepMind's AlphaGo model, which combines traditional Monte Carlo Tree Search (MCTS) rollout strategies with deep neural networks (policy and value networks) to intelligently select moves in the game of Go. 

Go presents an enormous search space due to high branching factors ($~250$ legal moves per turn) and deep search depths. AlphaGo limits the search space using:
1. **Policy Networks**: Convolutional neural networks trained on expert human games to predict move probabilities for given board states.
2. **Value Networks**: Neural networks trained to evaluate position win probabilities, replacing deep random rollouts.
3. **Reinforcement Learning Self-Play**: Continuously improving model policy weights by playing millions of games against previous iterations.

Key engineering challenges include preventing overfitting, managing massive parallel compute requirements, and balancing exploration vs. exploitation during tree search. AlphaGo achieved a historic milestone by defeating top human professional Go players.

## 2. System Architecture & Methodology

### 2.1 Game State & Tree Representation
- **Game Implementation**: `TicTacToe` class supporting arbitrary grid sizes ($3\times3$, $4\times4$, $5\times5$).
- **Search Tree Nodes**: `Node` class maintaining state representation, parent links, child lists, visit counts (`visits`), and accumulated reward (`value`).

### 2.2 Algorithmic Design Choices
- **Selection Policy**: Upper Confidence Bound for Trees (UCT) formula:
  $$\text{UCT}(n) = \frac{\text{value}(n)}{\text{visits}(n) + \epsilon} + c \cdot \sqrt{\frac{\ln(\text{parent.visits} + 1)}{\text{visits}(n) + \epsilon}}$$
  with exploration weight parameter $c = 1.4$.
- **Rollout Policy**: Semi-tactical random rollout policy. The agent plays random legal moves until terminal state, but takes an immediate winning move if detected.
- **Opponent Policy**: Completely random opponent to evaluate baseline search tree adaptability without assuming domain-specific opponent heuristics.
- **Backpropagation**: Traverses upward from terminal rollout nodes, updating visit counts and incremental reward values.

## 4. Discussion, Pros & Cons

### Pros
1. **Computational Speed on Small Grids**: MCTS completes decisions quickly on $3\times3$ boards ($0.16\text{s} - 0.71\text{s}$).
2. **Domain-Agnostic Exploration**: UCT selection effectively balances trying unexplored move branches vs. exploiting winning paths.
3. **Competitive Baseline**: Achieves a positive $50\% - 60\%$ win rate against random opponents on $3\times3$ boards.

### Cons & Limitations
1. **Poor Scalability**: On $4\times4$ and $5\times5$ boards, the search space explodes exponentially. Pure random rollouts rarely hit winning terminal states, forcing the agent into passive draw-seeking behavior ($98\% - 100\%$ draw rates).
2. **Low Sample Efficiency**: Increasing simulation budget from $1,000$ to $50,000$ iterations on $3\times3$ only improved win rate marginally from $52\%$ to $60\%$.
3. **Human Beatability**: A human player can easily defeat or draw this agent on $4\times4$/$5\times5$ grids due to its defensive draw bias, and can beat it on $3\times3$ with minor tactical practice.
